1. High-Level ArchitectureThe current architecture is a Modular Monolith. The entire backend runs as a single Node.js process deployed within a Docker container, but the internal code is strictly segregated by business domain.Client Layer: A React Single Page Application (SPA) communicating via REST over HTTPS.API Gateway / Proxy: Nginx (running in a Docker container) routes traffic to the backend and serves static assets.Application Layer: A Node.js (Express/NestJS) application containing isolated domain modules.Background Worker: A separate Node.js process (or thread) running BullMQ, listening to Redis for heavy tasks (AI API calls, resume parsing).Data Layer: A single PostgreSQL database with logically separated tables. Redis acts as the message broker for background jobs and caching layer.External Integrations: Cloud Storage (AWS S3) for PDFs and LLM Provider (Google Gemini) for AI analysis.2. Module Boundaries (Bounded Contexts)To prepare for microservices, modules must not bypass each other's service layers. Cross-module SQL joins are strictly forbidden. If the Jobs module needs recruiter details, it must call RecruiterService.getById(), simulating network calls in a microservice architecture.ModuleCore ResponsibilityOwned Database TablesAuthIdentity, authentication, JWT issuance.usersProfilesStudent and Recruiter/Company metadata.students, recruiters, companiesJobsJob lifecycle (posting, searching, filtering).jobsApplicationsApplication tracking and status updates.applicationsAI & ResumesPDF parsing, LLM orchestration, storage.resumes, ai_analysesCross-Module Communication: Modules communicate synchronously via Service-to-Service method calls or asynchronously via an internal Event Emitter (e.g., UserDeleted event triggers the Jobs module to cascade deletions).3. 4. Data FlowSynchronous Flow (Standard CRUD)Example: A recruiter posts a job.React client sends POST /api/v1/jobs with the JWT in the header.Express router routes the request to the Jobs module.Auth Middleware intercepts, validates the JWT, and attaches userId and role to the request.JobsController validates the payload.JobsService saves the record to PostgreSQL.Controller returns 201 Created to the client.Asynchronous Flow (Background Jobs)Example: A student requests AI Resume Analysis.Client sends POST /api/v1/resumes/:id/analyze.AiController receives the request and pushes a job payload to the Redis Queue via BullMQ.Controller immediately returns 202 Accepted (non-blocking).The decoupled Worker process picks up the job from Redis.Worker fetches the PDF, parses the text, and calls the external Gemini LLM API.Worker saves the result to PostgreSQL ai_analyses table.Client periodically polls GET /api/v1/resumes/:id/analysis to fetch the completed result.5. Security ArchitectureStateless Authentication: JWT-based auth. Tokens are stored in HTTP-only, secure cookies (to prevent XSS) or memory on the frontend.Role-Based Access Control (RBAC): Every route has a role guard. A student cannot access POST /api/v1/jobs.Network Security: All container traffic is isolated in a Docker network. PostgreSQL and Redis do not expose ports to the public internet—only the Node.js API and Nginx are exposed.Data Validation: Strict DTO (Data Transfer Object) validation using a library like Zod or class-validator before data reaches the service layer.Injection Prevention: ORMs/Query Builders (Prisma, Kysely, or TypeORM) used exclusively to utilize parameterized queries, eliminating SQL injection risks.6. Future Microservice Migration Plan (Strangler Fig Pattern)When the monolith reaches its scaling limits, the transition to microservices will follow these steps without rewriting the application:Phase 1: Extract the Worker (Compute Scaling)Deploy the BullMQ background worker as a separate Docker service on an independent server to handle intensive AI tasks without starving the main API of CPU cycles.Phase 2: Extract the Auth Service (Identity Layer)Move the /modules/auth folder to a new repository.Give it an independent database containing only the users table.Implement an API Gateway (e.g., Kong) to route /auth traffic to the new service, and validate tokens for all other traffic before it hits the monolith.Phase 3: Extract the AI & Resume Service (Heavy I/O)Extract the AI module into its own service. This allows it to scale independently based on usage (e.g., during peak placement season when uploads spike).Phase 4: Event-Driven ArchitectureReplace internal Node.js event emitters with a distributed message broker (Apache Kafka or RabbitMQ).Example: When a recruiter deletes a job in the Jobs Service, it publishes a JobDeleted event to the message broker. The Applications Service consumes this event and updates all related applications to "Archived."
